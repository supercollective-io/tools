# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users and purpose

Participants in a live collective gathering use Hub to find the current invitation,
Polymind to contribute words and receive released encounters, and Puck to move a
shared puck towards an option. Operators prepare and run these activities.
The user delegated redesign decisions to the project's purpose and existing behaviour.

## Capabilities and constraints

Hub shows one invitation and uses full-page navigation. Polymind distinguishes
automatic inclusion of saved writing, frozen revisions and explicit publication. Names do not
authenticate participants. Puck's server owns identity, physics and lifecycle;
live participants see only their own magnet, whereas authorised replay shows
recorded inputs. Each app remains independently deployable.

## Operating context

Participant phone use during live gatherings and operator desktop use are the
working design priorities. Physical-device and venue usability remain unverified.
Synthetic tests establish software behaviour, not artistic usefulness.

## Evidence on hand

App READMEs, AGENTS.md files, existing browser source and disposable browser tests.
No private event content is design material. No provider rehearsal or deployment
is authorised by a design task.

## Product principles

- Put the current participant task within easy reach.
- Keep private operation distinct from participation and projection.
- Preserve recovery, identity and publication boundaries.
- Support keyboard use, reflow and readable contrast.

## Brand commitments

The user requests functional, bold, almost Swiss design, confident with occasional
provocative cheekiness. Align with the performance description: temporary collective
intelligence, differences, contradictions and collective power. Preserve the agreed
Polymind question without supplementary prescribed examples or reassurance.

The user excludes non-functional UI text for now. Do not add slogans or
performance rhetoric to controls or participant pages.

Interface copy must be functional. Avoid language about belonging, togetherness
or making space unless it is an explicit activity instruction. The agreed
performance question and participant/generated content are distinct from UI copy.
