# Sessions own identity; operations consume snapshots

Polymind remains one Node process with local modules. Its event store owns guest identity, authored revisions, round closure and immutable snapshots. Analysis, bounded voice and the packaged Match worker consume snapshots without starting the continuous composer. Completion and publication are separate mutations.

The existing append-only microphone journals retain one writer and frozen model configuration. A session can have several rounds and voice runs; ending a run does not end the event. One continuous stream is active per process. SQLite and journal locks require one application replica and a durable volume.

Match is maintained in `packages/match` in this repository. Development and deployment use its single lockfile and environment, with an editable development install and a non-editable production install excluding development dependencies. Polymind launches the worker directly from that environment. Its CLI, research tools and process boundary remain independent of Polymind's session orchestration. Puck is maintained in `apps/puck` with the shared pnpm workspace and root checks, but retains its own process, identity, SQLite database, recordings and Docker deployment. It does not import Polymind session internals or run in its image. The participant hub is maintained in `apps/hub` with root verification and browser checks. It retains its own dependency-free Node service, operator authentication, atomic JSON state, Docker image and deployment. It links to participant destinations without importing application internals or owning their identities. Flight remains in a separate repository. There is no shared sign-in or service broker.
