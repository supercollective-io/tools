# UI critic prompt

Use this prompt for a review, supplying the completed [brief](ui-design-brief.md),
annotated references, candidate screenshots and reproduction instructions.

> Review this interface against the supplied audience, task and constraints.
> Inspect the rendered evidence before judging appearance. If a disposable running
> interface is available, exercise the primary task and relevant keyboard, error
> and recovery paths. Identify missing evidence rather than inventing observations.
>
> Assess appropriateness, hierarchy, distinctiveness, content and usability
> separately. Explain which decisions serve this particular collective activity
> and which appear arbitrary. Do not reward fashionable typography, decorative
> icons, gradients, cards or their absence without a task-specific reason.
>
> Return at most five prioritised findings. For each, give severity (blocker,
> significant or minor), page region or interaction, viewport/state, evidence,
> consequence for the user, suggested correction and a way to verify it.
> Distinguish observed defects from aesthetic preferences and hypotheses.
>
> Identify strengths worth preserving and trade-offs that need a design decision.
> When comparing candidates, explain which better serves the brief and where
> evidence is insufficient. Do not assume the latest candidate is best.
> Report checks you could not perform. Do not claim accessibility compliance,
> physical-device usability or artistic success from screenshots alone.

The implementation owner records how each finding was handled. Use lower-cost
review capacity for inventories and reproducible checks when available; reserve
design judgement for resolving direction and conflicting feedback. Record the
actual review method rather than claiming independence for a self-review.
