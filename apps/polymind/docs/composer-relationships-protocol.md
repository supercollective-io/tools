# Supported relationships — frozen development protocol

## Question

Do explicit, source-supported relationships help the composer develop the same
selected evidence? Compare identical nodes with and without generated support,
opposition, qualification and correction edges. This is a small graph-inspired
representation experiment; no graph database, indexing package or community
detection is involved.

Reuse the two accepted belonging extractions from the preceding slice. The
services extraction failed its record-count contract: preserve that case as
unavailable in both arms rather than repairing it or silently dropping it from
the report. Verify the prior attempt's source-case fingerprint before reuse.
Keep its original extraction cost and 12–18 second preparation time visible;
this comparison measures the additional relationship step.

## Controlled implementation

Select nodes once by the existing deterministic selector at a 560-token local
allowance, leaving room for relationship metadata under the 800-token source
packet limit. Both arms receive exactly those nodes in the same order. These
packets are smaller than the preceding slice's packets, so its saved compositions
are not the no-edge control: generate a new matched control for each snapshot.

The reader sees only selected nodes, with original quotes distinguished from
generated interpretations. It receives no full source or omitted material from
which to introduce additional facts into the edges. Request up to four edges,
with zero-based endpoint positions, one supported relationship kind and a brief
generated interpretation. An empty edge set is valid. Different topics or
different speakers do not establish opposition. A correction requires a revised
claim or an explicit correction, not merely a contrast.

Validate endpoint bounds, distinct endpoints, allowed kinds, duplicate edges and
deterministic order. These checks establish structure, not semantic support.
Retain the reader's complete result. Add whole edges under the 760-token local
selection ceiling, record deferred edges, and verify the final packet is at most
800 provider-counted tokens. Never remove or change nodes to fit an edge.

Use Terra composition and Luna relationship reading, both reasoning `none`,
4,096 output-token ceilings and 120,000 ms timeouts. Reuse the prior slice's
common instructions, source availability and exact prefixes. Use natural
completion through the existing Chat adapter. Run one response per arm and
accepted snapshot: four composer responses and two reader calls. Rotate arm
order across snapshots. No retries.

## Assessment and advancement

Freeze this protocol, source cases, accepted records, configuration and order
before dispatch. Keep this key out of prompts. Inspect whether an edge is
supported by its endpoint quotes, particularly whether attention versus anonymity
is being mistaken for a contradiction, or an unfinished thought for a completed
correction. Record unsupported edges even if the resulting composition ignores
them. Evaluate extraction, node selection, edge interpretation and composition
as separate stages.

Assess anonymised complete outputs against available sources and then inspect
the packets independently. Use the participant-experience criteria: distinctive
representation and an opportunity for conversation, supported by continuity and
pacing. A factual edge does not establish participant recognition. Do not require
every voice or edge to appear in the collective.

Advance edges only if their selected meanings are supported and the matched
compositions offer useful development without consequential flattening. Report
the extra input, reader delay and cost. An isolated attractive phrase is not
evidence of a reliable improvement; confirmation still requires fresh exchanges.
This slice isolates relationship value, not a 25% compression claim.

Test unchanged selected-node arrays, source exclusion, endpoint validation,
deterministic ordering, budgets and failure handling. Run full verification before
real calls. Use the shared US$5 ledger and a US$0.50 slice cap, including token-count
reservations and all failures. Keep exact output prefixes and every attempted arm.

Run `mise exec -- node --env-file-if-exists=.env src/representation-experiment.ts
relationships runs/composer-pilot/<accepted-extraction-attempt>` as one command.
An optional final argument links a previous relationship attempt. Save outcomes
under a new ignored `runs/composer-pilot/relationships-<uuid>/` directory and
commit findings before implementing another representation.
